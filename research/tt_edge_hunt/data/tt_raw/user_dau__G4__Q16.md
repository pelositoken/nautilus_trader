### How this was built
- Daily active users counts the unique addresses that make a revenue-generating transaction with a project over a fixed 24-hour window; each cell is that project's value for the calendar day, read one row per project per day with no averaging across days.
- Window: every calendar day from 2026-03-01 through 2026-05-31, the range the question named.
- Each project is read at its own project level (project aggregate, no product or chain split).
- Not reached: Jupiter and Render Network daily active users — Token Terminal does not track this metric for those two projects, so no column is shown for them.

Caveat: this total sums precomputed unique-count buckets, so identities present in more than one time or entity bucket can be counted more than once. It is an upper bound, not a deduplicated unique count.

_Token Terminal doesn't track Jupiter's active users (daily). Token Terminal doesn't track Render Network's active users (daily)._
